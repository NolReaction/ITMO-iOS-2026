# Демонстрация SwiftLint

`Example.swift` проверяется линтером, но не включён в app target.
Финальная версия примера проходит выбранные правила без предупреждений.

## Показ предупреждения и исправления

1. Открыть `Example.swift` и временно заменить его содержимое:

```swift
func lintExample() -> String {
    let ab = 42
    let optionalTitle: String? = "Demo"
    let title = optionalTitle!
    return "\(title): \(ab)"
}
```

2. Нажать ⌘B, затем ⌘5. Появятся `identifier_name` и `force_unwrapping`.
3. Переименовать `ab` в `answer` в обоих местах, а `optionalTitle!` заменить на
   `optionalTitle ?? "Untitled"`. Ещё раз нажать ⌘B: оба замечания исчезнут.
4. Для показа уровня error временно использовать имя `a` вместо `ab` в обоих
   местах. Снова собрать проект; затем вернуть исправленный пример.

Сами нарушения учебные: `String?` может быть nil, а `!` принудительно извлекает
значение. В этом примере строка есть, но линтер отмечает выбранную конструкцию.

## Показ исключений

Конфигурация исключает целую папку `SwiftLintDemo/Excluded` и отдельно файл
`SwiftLintDemo/IgnoredFile.swift`.

1. Создать `IgnoredFile.swift` рядом с `Example.swift` и положить в него учебный
   пример с другим именем функции, например `ignoredExample`.
2. Убедиться, что Target Membership у учебных файлов пустой, и запустить ⌘B.
   Замечания из исключённого файла не появятся.
3. В `.swiftlint.yml` временно убрать только строку `- SwiftLintDemo/IgnoredFile.swift`.
   После ⌘B замечания этого файла появятся. Вернуть исключение.
4. Аналогично проверить любой `.swift` внутри `Excluded`: исключается вся папка.
5. После демонстрации удалить временные файлы и вернуть исправленный `Example.swift`.

Это примеры настройки области проверки, а не способ скрывать замечания рабочего кода.
