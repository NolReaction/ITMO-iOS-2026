# WatchNext: фильмы и сериалы

Дмитрий Сломов, группа 4140.

Полное приложение: лабораторные 1–6 и проект WatchNext на SwiftUI/MVVM.
Финальная версия включает SwiftLint, четыре unit-теста и два UI-теста WatchNext.
Два unit-теста и два UI-теста шестой лабораторной также сохранены.

## Запуск

1. Установить SwiftLint: `brew install swiftlint`.
2. Открыть `ITMO-proj.xcodeproj` в Xcode 26.2 или совместимой более новой версии.
3. Дождаться загрузки Alamofire 5.10.2, выбрать схему `ITMO-proj` и iPhone Simulator с iOS 26.2+.
4. Нажать ⌘R. В меню выбрать «WatchNext: Фильмы и сериалы».

Для реального каталога и поиска нужен собственный ключ ПоискКино. В приложении
открыть настройки справа вверху, ввести ключ и сохранить. Он хранится в Keychain,
не включён в исходники и не нужен для автоматических тестов WatchNext.

## Возможности и устройство

- Каталог и поиск фильмов: URLSession, async/await, `actor WatchNextAPI`.
- Отдельные модели JSON и приложения; очистка строк, обработка отсутствующих полей.
- Обработка сетевых ошибок, HTTP-статусов и ошибок декодирования JSON.
- Личный список и статусы просмотра: SwiftData, `WatchNextLibraryViewModel`.
- Выбор фильма на вечер из запланированных, фильтр по жанру и исключение прошлого выбора.
- Простые настройки: `@AppStorage`/UserDefaults. Ключ API: Keychain.
- Alamofire используется в Lab6 для GET/POST; WatchNext обращается к URLSession напрямую.

Добавление фильма в личный список является локальной операцией SwiftData.
POST-запрос показан отдельно в шестой лабораторной.

## SwiftLint

В Build Phases приложения находится Run Script SwiftLint. При каждой сборке он
читает `.swiftlint.yml` из папки проекта. User Script Sandboxing для app target
установлен в No; Based on dependency analysis для скрипта выключен.

Проверяются `ITMO-proj/Lab6`, `ITMO-proj/Project` и `SwiftLintDemo`.
Настроены четыре стандартных правила: длина строки, имена, force unwrap и пробелы
в конце строки. Пороги правил сохранены; замечания исправлены в исходниках.
Рейтинг JSON `kp` переименован в Swift-модели в `kinopoisk`, а `CodingKeys`
сохраняет исходное имя ключа сервера.

Сервис Lab6 создаётся внутри MainActor-инициализатора ViewModel, что также
устраняет предупреждение компилятора об акторной изоляции.

Проверка вручную из этой папки, с ошибкой даже при предупреждениях:

```bash
swiftlint lint --strict --config .swiftlint.yml
```

Учебный `SwiftLintDemo/Example.swift` теперь исправлен. Сценарий временного
добавления нарушений и демонстрации исключений находится в
[`SwiftLintDemo/README.md`](SwiftLintDemo/README.md).

## Тесты WatchNext

В `ITMO-projTests/WatchNextTests.swift` четыре unit-теста:

1. JSON → фильмы: неверные записи пропускаются, пробелы очищаются, запасные поля используются.
2. Жанровый фильтр и выбор на вечер: при наличии другого фильма прошлый не повторяется.
3. Повторное добавление фильма не создаёт дубликат в SwiftData.
4. Изменение статуса и удаление сохраняются и видны через новый ModelContext.

В `ITMO-projUITests/WatchNextUITests.swift` два UI-теста:

1. Каталог → карточка → добавление → фильм появился в личном списке с исходным статусом.
2. Изменение статуса → скрытие просмотренного → повторное отображение при выключении фильтра.

UI-тесты передают аргумент `--watchnext-ui-testing`. Только в Debug он включает
локальный каталог из двух фильмов, отдельные настройки и базу в памяти.
Тесты не обращаются к API и не меняют обычную библиотеку пользователя.
Unit-тесты SwiftData также создают отдельное хранилище в памяти.
Обычный запуск приложения использует реальный API, настройки и постоянную базу.

Два теста хранилища объявлены `@MainActor ... async throws`: асинхронный вход
XCTest обходит известный сбой освобождения MainActor-объектов в Swift 6.2.
Сами операции SwiftData в этих тестах синхронные.
Описание проблемы: [swiftlang/swift#87316](https://github.com/swiftlang/swift/issues/87316).

Запустить всё: выбрать схему `ITMO-proj`, симулятор iPhone и нажать **⌘U**.
Тесты Lab6 остаются в файлах `ITMO_projTests.swift` и `ITMO_projUITests.swift`.

Из консоли Mac, например для установленного симулятора iPhone 17 Pro Max:

```bash
xcodebuild test \
  -project ITMO-proj.xcodeproj \
  -scheme ITMO-proj \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro Max' \
  -parallel-testing-enabled NO \
  CODE_SIGNING_ALLOWED=NO
```

Список доступных симуляторов можно получить командой `xcrun simctl list devices available`.
Сборка и XCTest требуют macOS с Xcode; статическое чтение файлов не заменяет их запуск.

### Проверенная финальная версия

01.11.2026 приложение собрано и проверено на macOS: **Xcode 26.2 (17C52),
iPhone 17 Pro, iOS 26.2**. Все **10 тестов прошли**: 6 unit и 4 UI, включая
четыре unit-теста и два UI-теста WatchNext. SwiftLint **0.65.1** с `--strict`
проверил 25 файлов: **0 нарушений, 0 серьёзных нарушений**.

[Успешный прогон и результаты тестов](https://github.com/NolReaction/ITMO-iOS-2026/actions/runs/41315722141).
Проверочный workflow находится в отдельной ветке `validation/watchnext-final`.
Swift-исходники и настройки проекта в проверке совпадают с финальной версией;
после проверки дополнена только документация. Тесты используют локальные данные,
поэтому доступность живого API и личного ключа проверяется обычным запуском каталога.
