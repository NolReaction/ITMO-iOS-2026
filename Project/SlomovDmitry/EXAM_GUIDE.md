# Swift: подготовка к зачёту на своём проекте

Задача этой шпаргалки: научиться объяснять свой код простыми словами. Не нужно запоминать все определения подряд. Открой указанный файл, найди приведённую строку через ⌘F, прочитай ответ вслух и покажи соответствующее действие в приложении.

## 1. Сколько ссылочных типов есть в Swift?

**Ответ:** «К ссылочным относятся классы и замыкания, включая функции. В современном Swift ссылочными типами также являются акторы».

Если преподаватель просит число, уточни классификацию: **три группы: классы, акторы и замыкания с функциями**. Функции не нужно считать ещё одной независимой группой: Swift Book рассматривает их как частный случай замыканий. В материалах без акторов обычно перечисляют две группы: классы и замыкания. Поэтому фраза «в Swift ровно два ссылочных типа» без уточнения неполна.

**Смысл ссылки:** при присваивании другой переменной используется тот же экземпляр. Например, два экрана могут работать с одним объектом библиотеки. Изменение через одну ссылку видно через другую.

**Где у меня:** `WatchNextLibraryViewModel` объявлен как `class`, `WatchNextAPI` как `actor`, а обработчик `responseData { response in ... }` в шестой лабе является замыканием.

Официальные разделы: [Classes Are Reference Types](https://docs.swift.org/latest/documentation/the-swift-programming-language/classesandstructures/), [Closures Are Reference Types](https://docs.swift.org/latest/documentation/the-swift-programming-language/closures/), [Actors](https://docs.swift.org/latest/documentation/the-swift-programming-language/concurrency/).

## 2. Чем значимый тип отличается от ссылочного?

У **значимого типа** присваивание даёт независимое значение. У **ссылочного** две переменные могут обращаться к одному экземпляру. Структуры и перечисления значимые; классы и акторы ссылочные. `Int`, `Bool`, `String`, `Array`, `Dictionary`, `Set` тоже имеют семантику значений.

```swift
struct CounterValue {
    var count = 0
}

var first = CounterValue()
var second = first
second.count = 10
// first.count остаётся 0.
```

С классом `second = first` обращался бы к тому же объекту. Для проверки идентичности экземпляров существует `===`; `==` сравнивает равенство согласно реализации типа. Не утверждай, что каждое присваивание массива немедленно физически копирует весь буфер: Swift может применять copy-on-write, сохраняя независимость значений.

**Где у меня:** `WatchNextShow` и `Lab6Post` являются `struct`, а `WatchNextSavedShow` и ViewModel являются `class`.

## 3. Что выбирать: struct, class, enum, protocol?

- `struct` объединяет данные и методы со значимой семантикой. Удобен для сетевой модели фильма.
- `class` нужен для экземпляра с общей идентичностью и состоянием. Поддерживает наследование. У нас это ViewModel и сохраняемая модель SwiftData.
- `enum` перечисляет варианты. У `WatchNextStatus` это `planned`, `watching`, `finished`.
- `protocol` описывает требования к возможностям типа. Например, `Decodable` требует поддержку декодирования. Ему могут соответствовать разные структуры и классы.

`final class` запрещает наследование от этого класса. `final` не делает свойства неизменяемыми и не обеспечивает потокобезопасность.

Частые протоколы, которые стоит узнавать в объявлениях своих моделей:

| Протокол | Зачем нужен |
|---|---|
| `Equatable` | Сравнивать значения через `==` |
| `Hashable` | Использовать значение в `Set` или ключом `Dictionary` |
| `Identifiable` | Предоставить `id`, по которому интерфейс различает элементы |
| `Codable` | Кодировать и декодировать данные |
| `Sendable` | Безопасно передавать значения между областями конкурентного выполнения |

**Где у меня:** `Project/Models/WatchNextSavedShow.swift`, поиск `enum WatchNextStatus` и `@Model`.

## 4. Что означают let, var, mutating и private(set)?

`let` задаёт константу, `var` изменяемую переменную. Для константы ссылочного типа нельзя заменить ссылку другим объектом, но его изменяемые свойства могут оставаться доступными.

Методу структуры, который изменяет её свойства, нужен `mutating`. Для класса такой модификатор не требуется. `private(set)` разрешает читать свойство снаружи, а менять только внутри типа. Поэтому экран читает `shows`, а ViewModel управляет результатами загрузки.

**Где у меня:** `WatchNextCatalogViewModel.swift`, поиск `@Published private(set)`; примеры `mutating` есть в заданиях первой лабы.

## 5. Optional, nil, !, ??, if let и guard let

`String?` означает «строка или отсутствие значения». Отсутствие обозначается `nil`. Это не пустая строка: `""` является существующим значением.

```swift
let optionalTitle: String? = nil
let title = optionalTitle ?? "Без названия"
```

`??` подставляет запасное значение. `optionalTitle!` принудительно извлекает значение и при `nil` аварийно завершает выполнение. `if let` выполняет блок только при наличии значения. `guard let` проверяет обязательное условие в начале: при отсутствии нужно выйти через `return`, `throw` или другой допустимый переход.

**Где у меня:** `WatchNextMovieResponse.swift`, поиск `guard let`; `WatchNextShow.swift`, поиск `imageURL` и `ratingText`. Если у фильма нет оценки или постера, это учитывается optional-свойствами.

Источник: [The Basics: Optionals](https://docs.swift.org/latest/documentation/the-swift-programming-language/thebasics/).

## 6. Что такое замыкание и @escaping?

Замыкание представляет блок кода, который можно передать и выполнить позже. Оно может захватить переменные из окружающего кода. Например, «после ответа сети выполни этот обработчик».

`@escaping` означает, что переданное замыкание может быть вызвано после завершения функции, которая его получила. Это характерно для сетевого completion-handler. Не путай его с асинхронной функцией `async`: это разные способы организации ожидания результата.

**Где у меня:** `Lab6APIClient.swift`, поиск `completion: @escaping`; `Lab6PostsService.swift`, поиск `result.map`.

## 7. ARC и слабая ссылка

ARC управляет временем жизни экземпляров классов через сильные ссылки. Когда сильных ссылок больше нет, экземпляр может освобождаться. Если два объекта сильно удерживают друг друга, появляется цикл, который мешает освобождению.

Замыкание тоже может удержать объект через `self`. Захват `[weak self]` полезен, когда иначе возникает цикл или результат уже не нужен после исчезновения владельца. Слабая ссылка может стать `nil`. Не нужно механически добавлять `weak` в каждое замыкание: сначала объясни, кто кого удерживает.

Источник: [Automatic Reference Counting](https://docs.swift.org/latest/documentation/the-swift-programming-language/automaticreferencecounting/).

## 8. Что у нас за архитектура MVVM?

**View** показывает интерфейс и передаёт действия пользователя. **ViewModel** хранит состояние экрана и координирует действия. **Model** описывает данные. Сетевые и сохраняющие операции вынесены в отдельные слои.

В WatchNext экран каталога вызывает ViewModel; она обращается к API; API получает JSON; ответ преобразуется в `WatchNextShow`; ViewModel записывает `shows`; экран отображает фильмы. В результате JSONDecoder и HTTP-проверки не размазаны по кнопкам SwiftUI.

**Где у меня:** `WatchNextDiscoverView.swift` → `WatchNextCatalogViewModel.swift` → `WatchNextAPI.swift` → `WatchNextMovieResponse.swift` → `WatchNextShow.swift`.

## 9. ObservableObject, @Published и состояние SwiftUI

`ObservableObject` позволяет наблюдать изменения объекта. `@Published` сообщает об изменениях его свойств. Экран, наблюдающий такой объект, обновляет зависимое отображение.

`@StateObject` хранит принадлежащий экрану наблюдаемый объект с устойчивым временем жизни в рамках идентичности этого экрана. `@State` используется для локального состояния, например выбранного жанра. `@EnvironmentObject` получает общий объект, который выше передали через `.environmentObject(library)`. `@AppStorage` связывает простую настройку с UserDefaults.

**Где у меня:** `WatchNextDiscoverView.swift`, поиск `@StateObject`; `WatchNextTonightView.swift`, поиск `@State`; `WatchNextView.swift`, поиск `environmentObject`; `WatchNextSettingsView.swift`, поиск `@AppStorage`.

Источник: [StateObject](https://developer.apple.com/documentation/swiftui/stateobject).

## 10. Что такое JSON и Codable?

JSON является текстовым форматом обмена данными. Сервер возвращает байты `Data`, а `JSONDecoder` пытается построить из них Swift-модель.

- `Decodable`: тип поддерживает чтение внешнего представления.
- `Encodable`: тип поддерживает запись во внешнее представление.
- `Codable`: объединение этих двух протоколов.

Само соответствие не отправляет сеть. `JSONDecoder` тоже не загружает адрес: ему передают уже полученные данные.

После декодирования мы ещё обрабатываем коллекции:

| Операция | Смысл и пример |
|---|---|
| `map` | Преобразовать каждый элемент: из записей библиотеки получить модели фильмов |
| `filter` | Оставить подходящие элементы: только выбранный жанр |
| `compactMap` | Преобразовать и убрать `nil`: `docs.compactMap { $0.show }` пропускает неверные записи API |
| `reduce` | Накопить общий результат: например, сумму количества слов |

**Где у меня:** `Lab6Post.swift` использует `Codable`; новая публикация `Lab6NewPost` использует `Encodable`; ответ каталога `WatchNextMovieResponse` использует `Decodable`. Ищи `JSONDecoder().decode` в двух сетевых клиентах.

Источник: [Encoding and Decoding Custom Types](https://developer.apple.com/documentation/foundation/encoding-and-decoding-custom-types).

## 11. Что значит Value: Decodable & Sendable?

Это ограничение обобщённого параметра: функция работает с разными типами результата, но каждый должен соответствовать **обоим** протоколам. `Decodable` нужен для разбора JSON, `Sendable` для безопасной передачи между областями конкурентного выполнения.

Тип результата выбирается в месте вызова: например, `WatchNextMovieResponse` или массив публикаций. Это позволяет не писать одинаковый HTTP-код для каждого варианта ответа.

**Где у меня:** `WatchNextAPI.swift` и `Lab6APIClient.swift`, поиск `func fetch<Value` или `func request<Value`.

## 12. Где GET, где POST и чем они отличаются?

GET запрашивает данные. POST отправляет данные для обработки, часто для создания ресурса. Конкретную семантику определяет API.

**Lab6:** в `Lab6PostsService.swift` метод `loadPosts` вызывает `requestPosts`. Клиент использует `method: HTTPMethod = .get`. В `createPost` явно указано `method: .post`, а `JSONParameterEncoder.default` кодирует тело новой публикации.

**WatchNext:** `WatchNextAPI.swift` использует URLSession. Поиск и стартовый каталог выполняются GET-запросами. «Добавить в мой список» сохраняет фильм локально в SwiftData, а не отправляет POST на сервер фильмов.

JSONPlaceholder является учебным сервисом: ответ на создание публикации имитируется, постоянной серверной записи ожидать нельзя. Источник: [JSONPlaceholder Guide](https://jsonplaceholder.typicode.com/guide/).

## 13. Какие сетевые ошибки мы обрабатываем?

Разделяй три ситуации. **Транспортная ошибка:** интернет отсутствует, связь оборвалась, истёк тайм-аут. **HTTP-ошибка:** сервер ответил, но статус неуспешный, например 404 или 401. **Ошибка декодирования:** ответ пришёл, однако его структура не совпадает с ожидаемой моделью.

В Lab6 отдельно сохраняются `error`, `statusCode`, `data`. Успешными принимаются коды 200–299. Для демонстрации 404 запрашивается несуществующая публикация; для ошибки JSON ожидается массив, когда сервер отдаёт один объект.

**Где у меня:** `Lab6APIClient.swift`, поиск `let error = response.error`, `if let code`, `JSONDecoder`; кнопки вызывают `testHTTPError` и `testDecodingError`. В WatchNext ищи `WatchNextAPIError`, `URLError` и `response.statusCode`.

## 14. Асинхронность, конкурентность и параллельность

Асинхронная операция позволяет не держать вызывающий код в блокирующем ожидании результата. Конкурентность означает, что несколько задач продвигаются в перекрывающиеся периоды. Параллельность означает одновременное выполнение, например на разных ядрах.

Сетевой запрос может ожидать ответ, пока интерфейс принимает нажатия. Для этого необязательно выделять отдельный поток, который всё время ждёт. Очередь задач и поток не одно и то же: очередь задаёт порядок выполнения, а системой управляются потоки, на которых задачи исполняются.

## 15. Где у нас GCD?

В пятой лабе `DispatchQueue.global(...).asyncAfter` запускает анализ на фоновой очереди. Передаётся снимок массива строк `snapshot`, а не объекты SwiftData вместе с контекстом. После вычисления `DispatchQueue.main.async` публикует результат для интерфейса.

`asyncAfter` откладывает старт, не блокируя поток на время задержки. В шестой лабе `responseData(queue: processingQueue)` направляет обработчик ответа на выделенную очередь. Там выполняются декодирование и последующие преобразования. ViewModel переносит обновление состояния на главную очередь.

**Где у меня:** `Lab5ViewModel.swift`, поиск `snapshot` и `DispatchQueue`; `Lab6APIClient.swift`, поиск `processingQueue`; `Lab6ViewModel.swift`, поиск `DispatchQueue.main.async`.

Источник: [DispatchQueue](https://developer.apple.com/documentation/dispatch/dispatchqueue).

## 16. async, await и Task

`async` обозначает функцию, выполнение которой может приостанавливаться. `await` отмечает возможную точку приостановки. `Task` создаёт задачу, из которой удобно вызвать async-функцию, например после нажатия кнопки.

**Важно:** `Task { ... }` сам по себе не обещает фоновый поток. Задача может наследовать изоляцию вызывающего кода. `await` тоже не означает «создать новый поток». Тяжёлый синхронный цикл внутри MainActor способен подвесить интерфейс.

**Где у меня:** в `WatchNextDiscoverView.swift` ищи `Task { await viewModel.load`; в API — `try await session.data(for: request)`. Во время сетевого ожидания выполнение приостанавливается, результат обрабатывается после получения.

## 17. Actor, MainActor, Sendable и nonisolated

**Actor** изолирует изменяемое состояние и последовательно допускает работу с ним. У нас сетевой сервис объявлен `actor WatchNextAPI`. После `await` другой код мог уже изменить состояние актора: нельзя считать всю async-функцию одной неделимой операцией.

**MainActor** является глобальным актором, связанным с главным потоком. У нас ViewModel помечены `@MainActor`, чтобы состояние интерфейса обслуживалось согласованно.

**Sendable** говорит о возможности безопасной передачи значения между областями конкурентного выполнения. Это не автоматическое создание потока и не кодирование JSON.

**nonisolated** убирает соответствующую акторную изоляцию у объявления. В нашем проекте по умолчанию настроен MainActor; чистые модели и обработчики специально доступны без этой привязки. Это не разрешение небезопасно менять общие данные.

Источники: [Concurrency](https://docs.swift.org/latest/documentation/the-swift-programming-language/concurrency/), [Sendable](https://developer.apple.com/documentation/swift/sendable), [MainActor](https://developer.apple.com/documentation/swift/mainactor).

## 18. Где и зачем хранятся данные?

**SwiftData:** фильмы личного списка. `WatchNextSavedShow` помечен `@Model`. `ModelContainer` описывает хранилище, `ModelContext` позволяет читать, вставлять, удалять и сохранять объекты. В `WatchNextLibraryViewModel` после ошибки сохранения вызывается `rollback`.

**UserDefaults через @AppStorage:** простые предпочтения, например показывать рейтинг и скрывать просмотренное.

**Keychain:** ключ API. В `WatchNextCredentials.swift` используются `SecItemCopyMatching`, `SecItemAdd`, `SecItemUpdate`, `SecItemDelete`. Ключ не нужно прописывать строкой в исходниках или коммитить.

Открой карточку, добавь фильм, измени статус, перезапусти приложение: личный список сохраняется. Источники: [ModelContext](https://developer.apple.com/documentation/swiftdata/modelcontext), [настройки и AppStorage](https://developer.apple.com/documentation/foundation/accessing-settings-from-your-code), [Keychain](https://developer.apple.com/documentation/security/using-the-keychain-to-manage-user-secrets).

## 19. Unit-тест и UI-тест

Unit-тест вызывает конкретную логику и сравнивает результат с ожиданием. Для WatchNext это правила выбора, преобразование данных или операции библиотеки. UI-тест запускает приложение, нажимает элементы и проверяет пользовательский сценарий.

Схема теста: **подготовка → действие → проверка**. `XCTAssertEqual` сравнивает значения, `XCTAssertTrue` проверяет условие, `waitForExistence` ждёт элемент интерфейса.

**Где у меня:** `ITMO-projTests/WatchNextTests.swift` и `ITMO-projUITests/WatchNextUITests.swift`. Старые файлы `ITMO_projTests.swift` и `ITMO_projUITests.swift` проверяют Lab6. Запуск всех тестов: ⌘U. Детерминированные тесты не должны зависеть от живого сервера, личного API-ключа или ранее сохранённых фильмов.

Источник: [XCTest](https://developer.apple.com/documentation/xctest).

## 20. Что сделал SwiftLint?

Это статическая проверка исходников. `.swiftlint.yml` выбирает папки и правила, а Run Script в Build Phases запускает проверку при сборке. `PATH` помогает найти установленную Homebrew программу; `$SRCROOT` означает папку проекта.

Наши правила: `line_length`, `identifier_name`, `force_unwrapping`, `trailing_whitespace`. Мы настроили стандартные правила, а не написали собственный анализатор. `included` задаёт область проверки, `excluded` исключения. Исправления нужно делать в коде; ослаблять пороги ради исчезновения предупреждений не требуется.

`lint` сам не исправляет код. Предупреждения обычно не мешают сборке; нарушение с уровнем error завершает проверку ошибкой. SwiftLint не доказывает правильность работы приложения и не заменяет тесты.

Источник: [SwiftLint README](https://github.com/realm/SwiftLint).
